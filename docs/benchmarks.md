## Key Takeaways

- **CPU scaling:** On 4 CPU cores with NumPy `float64` and SciPy L-BFGS refinement, `reluopt` fits problems up to $`262{,}144 \times 32`$ in 7.1 seconds and $`16{,}384 \times 256`$ in 46.4 seconds across Gaussian, correlated, and heavy-tailed ($`t_3`$) inputs as well as smooth nonlinear targets.
- **GPU speedup:** Offloading direction search and L-BFGS refinement to CUDA (`float32` search + final `float64` output-weight refit) speeds up the $`4{,}096 \times 128`$ workload on an NVIDIA L4 by **$`2.6\times`$** (16.0 s to 6.2 s with CUDA graphs) and the $`262{,}144 \times 32`$ workload on an A100 by **$`2.8\times`$** (5.0 s to 1.8 s), reaching final objectives within `0.012%` of the CPU `float64` solve.

For comparisons with SCNN, adelie, SGD, Adam, and AdamW on real tabular datasets, see [Real-Data Comparison](real-data.md) and [AdamW Initialization](adamw-initialization.md).

## Workload Definitions and Solver Settings

- **Synthetic data generation:** Except for the smooth nonlinear workload, targets are generated by a sum of $`k \in \{4, 8, 16, 32\}`$ unit-norm ReLU units with Gaussian noise. Correlated inputs share a common Gaussian factor; Student-$`t`$ ($`\nu=3`$) inputs are scaled to unit variance. The smooth nonlinear target is $`\sin(2x_0) + 0.3(x_1^2 - 1) + 0.2 x_2 x_3`$ plus Gaussian noise.
- **Regularization:** The `Small` workload uses $`\lambda / n = 0.01`$; all other workloads use $`\lambda / n = 0.003`$.
- **Solver settings:** `max_iter=40`, `add_per_round=8`, `gated_every=2`, `max_cols=256`, `sketch_m=8192`, `certify_every=0`, `time_budget=180.0`, `final_verify=True`, `final_diagnostics=True`. Every fit converged on its final Lasso subproblem with KKT residual below $`10^{-10}`$.
- **Environment:** Measured on 2026-10-15 with `reluopt` 0.3.0, Python 3.12.10, NumPy 2.5.4, SciPy 1.18.1, and PyTorch 2.10.0+cu128 (TF32 disabled). Standard/GPU suites use data seed `177`; larger scale workloads use seed `811`. Full per-run records are stored in [`benchmarks/results.json`](../benchmarks/results.json).

## Reproducing the Benchmarks

From a repository checkout:

```bash
uv sync --extra dev --extra compute

# Local smoke test
uv run --extra dev python -m benchmarks.run --suite smoke

# Remote Modal benchmarks
uv run --extra compute modal run -m benchmarks.modal_app --suite standard
uv run --extra compute modal run -m benchmarks.modal_app --suite scale \
  --seed 811 --repeats 1
uv run --extra compute modal run -m benchmarks.modal_app --suite wide \
  --variants default,device,graph --backends cpu,cuda
uv run --extra compute modal run -m benchmarks.modal_app --suite tall \
  --variants default,device,device64,graph --backends cpu,cuda --gpu-type A100
```

Use `--threads` to set BLAS thread count, `--output` to specify the output JSON path, and `--profile` (local) or `--profile-run` (Modal) for `cProfile` call breakdowns.
